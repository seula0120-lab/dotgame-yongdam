# R1-fileurl 계획: GAME_DESIGN.md가 "게임을 어떻게 실행하는가"를 말하게 한다

## Summary
사람이 index.html을 더블클릭(file://)하면 빈 화면이 나온다. 브라우저가 file://에서 `<script type="module">`을 CORS로 막기 때문이다. http로는 정상 동작한다(에이전트 Chrome 확인, file://에서는 canvas 첫 픽셀이 투명). 원인은 코드 버그가 아니라 기획서의 실행 전제 부재다. 목표는 하나: **GAME_DESIGN.md가 게임 실행법을 말하게 한다.** 변경은 8장과 9장 "R1 항목" 문구뿐이다. 코드·AGENTS.md는 건드리지 않는다.

**R1은 통과하지 않았다.** 사람의 R1-1~R1-5 확인 결과는 아직 기록되지 않았다(사람의 직전 확인 보고에 채워지지 않은 템플릿 자리표시자가 남아 있었다). 이 계획은 R1 통과를 주장하지 않는다. 원장의 마지막 기록(critic_verdict OKAY, classificationEventId 1d17a4ee-4eaa-41f6-bc2b-a3f1ed6dbc1c, "AGENTS.md 사람 브라우저 확인 R1-1..R1-5만 남음, 소스는 7cf09f8 이후 불변")은 그대로이고 G001은 checkpointed blocked, goal은 paused다. HEAD=7cf09f8 (goal-1), 직전 582f809 (design-v1).

## Intent Diff
- 사람의 의도: 기획서대로 하면 열린다는 상태. 기획서가 애매하면 기획서를 먼저 고치고 사람에게 보여준 뒤 진행한다(AGENTS.md 개요).
- 현재 기획서: 실행 환경 전제가 없다. 그래서 "index.html을 연다"가 file://로 읽혔고 사람도 그렇게 읽었다.
- 변경 후: 8장이 실행 전제(http 정적 서버)를 못 박고, 9장 R1 줄이 사람에게 서버를 켜고 http://localhost:8000을 열라고 말한다.
- 스코프 락(사람 지시): GAME_DESIGN.md 8장 + 9장 "R1 항목" 문구만. AGENTS.md 수정 금지, index.html/src/*/test/* 수정 금지.

## 애매했던 GAME_DESIGN.md 항목과 이유
1. **8장 "기술 스펙" (122~124행) = "R3에 채운다."** — R1 검증 시점에 실행 환경 전제가 정의되지 않았다. 근본 원인.
2. **9장 R1 항목 (130행) "사람이 index.html을 열어 …"** — "index.html을 연다"는 파일을 직접 여는 것(file:// 더블클릭)을 함의한다. 이 문장이 사람을 빈 화면으로 보냈다.
3. **R1-3 "캔버스 논리 해상도 256x192, 표시 768x576"** — 캔버스가 뜬다는 것을 전제한다. file://에서는 모듈 로드 실패로 캔버스가 그려지지 않아 확인 자체가 불가능했다. (문구는 바꾸지 않는다. 1·2번 수정으로 전제가 충족된다.)
4. **2.1 / 4장** — 해상도·표시 규칙만 있고 실행 방식은 말하지 않는다. 별도 수정 불필요, 8장이 담당한다.
5. (잔여, 수정 불가) **10장 "서버"와 AGENTS.md 25행 "서버" 금지** — 게임 서버(백엔드)를 뜻한다고 읽는 것이 자연스럽지만 문장상 정적 개발 서버와 구분되지 않는다. 아래 OPEN 3 참고.

## RALPLAN-DR 원칙

2. 최소 변경: 허용 범위 밖은 열린 결정으로 올리고 조용히 건드리지 않는다.

4. 기술 제약 보존: ES modules/무빌드 유지.
