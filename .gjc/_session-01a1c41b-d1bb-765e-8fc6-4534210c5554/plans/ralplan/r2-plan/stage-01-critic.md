## Missing Evidence / 결함 (ITERATE 사유)
### 블로커 (확정적 누락)
1. **결정 목록 불완전 — 코드가 추측해야 하는 규칙이 문서/결정에 없음.**
   - 배달·클리어 판정 시점: 이동은 0.60초 보간 중인데 편지가 우편함 칸에 '들어간' 순간이 이동 시작인가 완료(600ms)인가. R2-12 '즉시 클리어'와 R2-14(동일 프레임 타이브레이크)가 이 정의에 의존. 또한 이동 중(0.6초) 시간 0이 되면 진행 중인 이동은 완료되는가 즉시 멈추는가(R2-7 '더 이상 움직이지 않고').
   - 우편함 칸 통행 규칙: 달팽이가 빈 우편함 칸에 들어갈 수 있는가? 현재 isWalkable은 '.'만 true라 새 문자 M/L을 그대로 두면 막힘/통행이 암묵적으로 결정됨. 4장 오브젝트 표에 편지/우편함 종류(이동 가능/불가) 결정 필요.
   - R2-4 '배달 표현'(사라짐 vs 우편함 안 표시)과 R2-14 타이브레이크는 본문에서 'D 결정'이라 하나 **D 번호가 없음** -> 결정표에 정식 항목으로 추가해야 함.
   - 타이머 표시 반올림(올림/내림): 60 시작 시 첫 1초 동안 60인가 59인가, 0 표시는 잔여 0ms에서만인가. R2-6/R2-7/R2-13 합격/불합격이 이 규칙에 좌우됨. DT_CAP(100ms) 때문에 타이머는 벽시계가 아닌 게임 시간이라는 점(백그라운드 탭 시 실시간 60초 아님)도 사람에게 한 줄 명시 필요.
2. **8색 규칙 vs 글자 렌더링 충돌 미식별.** R2-8은 타이머/문구 글자에 8색 외 색이 없다고 요구하나, canvas fillText/웹폰트는 안티앨리어싱으로 8색 밖 중간색을 만든다. D16이 '캔버스 기본 글꼴 vs 웹폰트'를 택일로 두는데 둘 다 R1-5/R2-8 위반 위험이 있다. 숫자·문구를 스프라이트(팔레트 인덱스 배열) 또는 안티앨리어싱 없는 비트맵 폰트로 그리는 선택지를 D16에 넣고, 합격 기준을 '픽셀 단위로 8색만'으로 검증 가능하게 해야 함(예: 확대 캡처 육안 확인 절차).
3. **goal 경계 불일치.** D16(폰트)·D12/D13(문구)이 'goal 3'로 분류돼 있으나 goal-2의 R2-6 타이머 숫자 표시에 글자(숫자/'초')가 이미 필요. 옵션 B 선택 시 v4에서 D16/D5를 확정해야 함. D8(타이머 시작: 페이지 연 순간)은 goal-3에서 타이틀 진입으로 바뀌어 goal-2 코드를 재작업 — B의 '재작업 최소' 주장과 모순되니 단점에 명시하거나 A를 재검토.
4. **구체 레벨 제안 부재(thin spec).** D1~D4는 '2개, L/M, 60초, 오른쪽 아래'로 수치만 있고 실제 격자 초안이 없음. 사람이 서명할 수 있도록 기획서 5장에 들어갈 구체 16x12 격자(편지/우편함/S 위치)와 '막다른 길 없이 클리어 가능한 해법 경로 + 필요 칸 수(×0.60초)가 제한 시간(60초) 안에 들어옴' 근거를 계획에 제시해야 함. 위험표가 '문서에 한 줄 적어 확인'이라고만 하는데 이는 계획이 이미 했어야 하는 산출물임. 60초 = 최대 약 100칸 이동 — 사람이 판단할 수 있는 수치로 적을 것.
