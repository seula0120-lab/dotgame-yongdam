# R2 계획 — 달팽이 우체부 (goal-2 / goal-3)

근거: GAME_DESIGN.md v3(164줄), AGENTS.md, src/logic.js·main.js·levels.js, test/logic.test.js 확인. 코드·기획서 수정 없음. `(에이전트 제안)`은 사람이 확정해야 하는 값이다.

## 1. Summary
R2는 두 goal이다. goal-2 = 편지를 우편함으로 밀어 배달하고, 레벨 1의 제한 시간이 흐른다. goal-3 = 승/패 판정과 화면 흐름(타이틀, 플레이, 클리어, 실패, R키 재시작). 기획서 3장·2.2·4장(편지/우편함)·5장·6장·9장 R2 항목이 비어 있으므로 **코드보다 먼저 design-v4 기획서 수정과 사람 서명**이 필요하다. R3(Space+방향키 2칸 이동, 사운드, 점수, 레벨 2·3)는 계획에 넣지 않는다.

## 2. Intent Diff
- 사용자 문구 '위협' -> 기획서에는 타이머 외 적/위협/장애물 오브젝트가 **없다**. 그래서 '위협'은 타이머/시간 초과로만 매핑한다. 위험물 오브젝트는 만들지 않는다. **사람 확인 필요: 다른 것을 의도했는가?**
- '레벨마다 다른 제한 시간' -> R2에는 레벨 1만 있다(레벨 2·3은 R3). 숫자는 지금 하나이고, 구조만 레벨별로 담을 수 있게 한다(기획서 2.2: 격자 옆에 숫자 표기).
- 이미 기획서에 확정된 것(재사용, 재논의 안 함): 편지는 줍지 않고 민다(2.1), 뒤가 벽/울타리/다른 편지면 달팽이·편지 모두 정지(2.1), 밀 때도 0.60초(2.1), 우편함 칸으로 밀면 배달·전부 배달하면 클리어(2.1), R키 = 현재 레벨을 처음 상태로 재시작(2.1), 시간 다 되면 패배(2.2). 당기기·되돌리기·일시정지·저장·난이도 선택은 10장 범위 밖.

## 3. RALPLAN-DR 요약
### Principles
1. 기획서 우선: 기획서에 없는 것은 만들지 않는다. 애매하면 기획서를 먼저 고치고 사람에게 보여준 뒤 코드를 쓴다(AGENTS.md).
2. 사람이 눈으로 확인 가능한 완료 조건: 테스트 통과는 완료가 아니다. R2-N 번호로 브라우저에서 확인한다.
3. 순수 로직 분리: logic.js는 canvas/DOM을 모르는 순수 함수. 화면 흐름 상태도 순수 함수로 둔다.
4. 숫자는 기획서에서만: 테스트 기대값은 기획서 숫자에서 가져오고, 코드가 하는 일을 베낀 테스트는 쓰지 않는다.
5. 층층이 쌓기: goal-2가 브라우저에서 동작한 위에 goal-3을 얹는다. 한 goal = 한 커밋(`goal-N:`).

### Decision Drivers (상위 3)
1. 기획서 공백이 크다(3장, 2.2, 편지/우편함, 문자, 시간 숫자, 색, 텍스트). 이 공백이 코드 착수 시점을 결정한다.
2. 사람 서명 횟수/지연 vs 재작업 위험(값을 나중에 바꾸면 테스트·levels.js 동시 수정).
3. UI 텍스트가 7장에서 'R3에 채운다'로 되어 있는데 R2 화면에 글자가 필요하다는 충돌.

### Options
**A. design-v4 한 번에 전부 작성 -> 서명 -> goal-2 -> goal-3 코드.**
- 장점: 서명 1회, 값 충돌 없음, 두 goal의 경계가 문서로 고정. 재작업 최소.
- 단점: 사람이 한 번에 많은 결정을 해야 하고 코드 착수가 늦다.
**B. 문서를 goal별로 분할: design-v4(goal-2분: 2.2 시간, 4장 편지/우편함, 5장 문자·숫자, 6장 색, 9장 R2-1~) -> goal-2 코드 -> design-v5(goal-3분: 3장, 텍스트, 9장 나머지) -> goal-3 코드.**
- 장점: 결정을 나눠 받고 goal-2를 빨리 브라우저에서 볼 수 있다. goal-3 결정을 goal-2 실물을 본 뒤 할 수 있다.
- 단점: 서명 2회, 타이머 표시 위치·텍스트 등 goal 간 걸친 결정이 어긋날 수 있다. 커밋 `design-v4`, `design-v5` 2개.
**C(비추천). 기획서 수정 없이 (에이전트 제안) 값으로 바로 코딩** — AGENTS.md '기획서를 먼저 고치고 사람에게 보여준 뒤 코드'에 위배되어 탈락.
**권고: B.** 경계가 분명하고(goal-2는 시간이 줄고 0이 되면 입력이 멈추는 데까지, goal-3은 판정·화면) 결정량을 나눌 수 있다. 단, 사람이 한 번에 보길 원하면 A.

### goal-2 (목표, 타이머)
- R2-1. 레벨 1 화면에 편지 [D1]개와 우편함 [D2]개가 보이고, 달팽이는 기존 시작 칸에 있다.
- R2-2. 편지가 있는 칸 쪽으로 방향키/WASD를 한 번 누르면 달팽이가 한 칸, 0.60초 동안 가고 편지가 같은 방향으로 한 칸 같이 밀린다.
- R2-3. 편지 뒤가 벽, 울타리, 다른 편지이면 달팽이와 편지가 모두 움직이지 않는다.
- R2-4. 편지를 우편함 칸으로 밀어 넣으면 그 편지가 배달된 것으로 사라지거나 우편함 안에 표시된다(표현은 D 결정 필요: 제안 = 편지가 화면에서 사라짐).
- R2-5. 편지를 줍거나 당길 수 없다. 달팽이가 편지 반대쪽으로 가도 편지가 따라오지 않는다.
- R2-6. 화면에 제한 시간 [D4]초가 [D5] 위치에 보이고 1초씩 줄어든다.
- R2-7. 제한 시간이 0이 되면 달팽이가 더 이상 움직이지 않고 타이머 0이 보인다(D7. 패배 화면은 goal-3).
- R2-8. 새로 그려진 편지·우편함·타이머 글자에 8색 외의 색이 보이지 않는다(기존 R1-5 유지).
- R2-9. 기존 R1-1~R1-5(이동 0.60초, 벽/울타리 막힘, 해상도, 맵 크기, 8색)가 그대로 동작한다.

### goal-3 (판정, 화면 흐름)
- R2-10. 페이지를 열면 타이틀 화면이 보이고 [D9] 키를 누르기 전에는 달팽이가 움직이지 않으며 타이머도 줄지 않는다.
- R2-11. [D9] 키를 누르면 플레이 화면으로 가고 그때부터 타이머가 줄기 시작한다.
- R2-12. 편지를 전부 우편함에 배달하면 즉시 클리어 화면이 보이고 타이머가 멈춘다(D14).
- R2-13. 제한 시간 안에 다 배달하지 못하고 0이 되면 실패 화면이 보인다. 시간이 남은 상태에서는 실패 화면이 나오지 않는다.
- R2-14. 마지막 편지를 배달한 바로 그 순간 시간이 남아 있으면 클리어이고, 시간 0과 마지막 배달이 같은 프레임이면 어느 쪽인지는 사람이 결정(제안: 클리어 우선 (에이전트 제안)).
- R2-15. 플레이 중 R을 누르면 레벨 1이 처음 상태(달팽이 시작 칸, 편지 처음 칸, 제한 시간 처음 값)로 돌아온다.
- R2-16. 클리어/실패 화면에서 R을 누르면 레벨 1이 처음 상태로 플레이를 다시 시작한다(D10). 타이틀에서 R은 아무 일도 하지 않는다.
- R2-17. 각 화면에 표시되는 글자는 사람이 확정한 문구(D12)와 일치한다.

## 9. 검증 계획
**단위 테스트(node --test test/)** — 기대값은 기획서 숫자에서:
- 한 칸 밀기 0.60초(600ms 도착, 599ms 미완료; 밀 때도 같음, 2.1).
- 편지 뒤가 벽/울타리/다른 편지/맵 가장자리면 달팽이·편지 위치 불변(2.1).
- 편지가 우편함 칸에 들어가면 배달 수 +1, 전부 배달하면 클리어(2.1).
- 타이머: 사람이 서명한 초 값(D4)에서 1000ms당 1초 감소, 0 이하에서 패배(2.2), 감소는 DT_CAP 100ms(2.1.1)를 따른다.
- 화면 전이: title->play(시작 키), play->clear, play->fail, clear/fail->play(R), title에서 R 무시(3장 서명 후).
- 격자: 레벨 1 16x12, 편지/우편함 문자 수가 D1/D2와 일치.
- 스프라이트 16x16, 인덱스 0~7(R1-4, R1-5 확장).
- 코드가 하는 일을 그대로 적은 테스트 금지(AGENTS.md).
**사람 브라우저 확인:** 위 R2-1~R2-17을 번호별로 확인. 스크린샷/fixture는 증거 아님. 완료 보고는 '무엇을 열어 어떤 번호를 볼지'로 쓴다.
**수동 점검:** `git diff`로 AGENTS.md 미변경, GAME_DESIGN.md 외 숫자 변경 없음 확인.

## 10. Escalation / Risk Gate
- 사람 서명 전에는 어떤 코드도 쓰지 않는다. design-v4(및 v5) 서명이 게이트.
