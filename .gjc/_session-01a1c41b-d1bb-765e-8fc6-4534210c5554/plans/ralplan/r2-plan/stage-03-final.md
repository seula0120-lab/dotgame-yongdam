## 1. Summary
goal-2 = 편지 밀기·우편함 배달·제한 시간 타이머(화면 표시 포함). goal-3 = 승/패 판정 화면, 타이틀/플레이/클리어/실패 흐름, R키 재시작. **규칙 전부(2.2, 3장, 4장, 5장, 6장 색, 9장 R2 항목)는 design-v4 한 번에 서명**하고, 화면 문구·글꼴(7장)만 별도로 분리해 서명할 수 있다. 코드 goal은 2개. Out(R3·10장): Space+방향키 2칸 이동, 사운드, 점수, 레벨 2·3, 줍기/당기기/되돌리기/일시정지/저장/난이도 선택, 위험물 오브젝트.

## 2. Intent Diff
- '위협' -> 기획서에는 타이머 외 적/위협/장애물 오브젝트가 **없다**. 타이머·시간 초과로만 매핑, 위험물은 만들지 않는다. **사람 확인: 다른 것을 의도했는가?**
- '레벨마다 다른 제한 시간' -> R2는 레벨 1뿐(2·3은 R3). 숫자는 하나, 구조는 레벨별로 담을 수 있게(2.2: 격자 옆에 숫자 표기).
- 이미 확정(2.1/2.2, 재논의 안 함): 편지는 민다, 뒤가 벽/울타리/다른 편지면 둘 다 정지, 밀 때도 0.60초, 우편함에 밀어 넣으면 배달·전부 배달하면 클리어, R키=현재 레벨 처음 상태로 재시작, 시간 다 되면 패배.

## 3. RALPLAN-DR
### Principles
1. 기획서 우선: 없는 것은 만들지 않고, 애매하면 기획서를 먼저 고쳐 사람에게 보여준 뒤 코드(AGENTS.md).
2. 완료 = 사람이 브라우저에서 R2-N 번호로 확인. 테스트 통과·fixture 스크린샷은 증거 아님.
3. logic.js 순수: canvas/DOM 모름. 상태 객체 -> 새 상태. 화면(screen)은 저장하지 않고 상태에서 파생.
4. 숫자는 기획서에서만: 테스트 기대값은 기획서 숫자, 코드가 하는 일을 베낀 테스트 금지. 레벨 격자는 5장 그대로 복사.
5. 층층이 쌓기·한 goal 한 커밋(`goal-N:`), 같은 시도 6회 초과 금지.

### Decision Drivers (상위 3)
1. 의미 결정(언제 확정·어떤 순서·시계)이 값 결정보다 경계 동작을 좌우한다 -> 문서에 먼저.
2. 서명 횟수·재작업(타이머 시작, 종료 표시가 goal 사이에서 바뀌는 비용).
3. 8색 규칙과 글자 렌더링(안티앨리어싱)의 충돌, 7장이 'R3에 채운다'인 점.

- 장점: 규칙이 한 문서에서 일관. 서명 중복 없음. goal-2에 쓰는 타이머 숫자·goal-3 종료 규칙이 서로 어긋나지 않음. 텍스트만 늦게 확정 가능.

## 5. 레벨 1 격자 초안 (에이전트 제안) — 기획서 5장 후보
기존 벽·울타리·시작 칸 그대로. 편지 `L` 2개, 우편함 `M` 1개 추가. 16열 x 12행, 문자: `#` 벽 `F` 울타리 `.` 바닥 `S` 시작 `L` 편지 `M` 우편함.
```
################
#..............#
#..F...........#
#..F......##...#
#...S..L....M..#
#..............#
#.......FFF.L..#
#..............#
#..##..........#
#..............#
#..............#
################
```
- 좌표(열,행): S(4,4), 편지A(7,4), 편지B(12,6), 우편함(12,4).
- 해법 키열(방향키): `→ → → → → → →`(7번: 칸 4->11, 두 칸 이동 후 5칸 밀어 편지A가 M으로) + `↓ → → → ↓`... 구체적으로 `↓ ←`는 쓰지 않는다. 달팽이는 (11,4)에서 `↓ ↓ ↓`(11,7까지) `→`(12,7) `↑ ↑`(편지B를 (12,5), (12,4)=M으로). 합계 7 + 4 + 2 = **13칸**(마지막 `↑ ↑` 포함 `↓↓↓→` 4칸 + `↑↑` 2칸).
- 시간: 13칸 x 0.60초 = **7.8초(최소)**. 제안 30초는 최소의 약 3.8배로 실수·우회 여유(되돌리기 없음)를 준다. 60초 대안(약 7.7배)은 긴장감이 거의 없다. 사람이 시연 후 조정(조정 시 기획서 숫자·테스트·levels.js 동시 수정).
- 막다른 길 위험: 편지가 벽/울타리에 붙은 구석으로 밀리면 클리어 불가 -> R키로만 복구. 초안은 편지A를 열린 가운데 행에, 편지B를 우편함 아래 열에 두어 첫 밀기가 안전하다.
- 해법 기록: 위 키열을 기획서에 적고 **해법 재생 단위 테스트**(키열 입력 -> 편지 2개 배달·클리어, 소요 시간 <= D4)를 필수로 둔다.

## 6. 상태 형태와 파일 변경

- GAME_DESIGN.md(design-v4): 2.2(시간·패배·시계 D20·D18~D23), 2.1.1 한 줄(D25), 3장 화면 흐름, 4장 편지·우편함 행(D22), 5장 격자+시간 숫자+해법, 6장 새 오브젝트 색 쓰임, 7장 문구(D13), 9장 R2-N, 상단 상태. AGENTS.md **수정 금지**.

- src/sprites.js: **이미 존재(PALETTE, FLOOR, WALL, FENCE, SNAIL)** — 수정해 편지·우편함·숫자 글리프 추가, PALETTE 재사용. src/strings.js 신규(UI 문구 한 곳). src/main.js: screen 파생 렌더, 입력 액션, 타이머 표시.

확인 방법: 8장대로 `python3 -m http.server 8000` 후 Chrome `http://localhost:8000`. (goal-2 단독 시점에는 타이틀이 없어 페이지를 연 순간 시작)
### goal-2
- R2-1. 레벨 1 화면에 편지 [D1=2]개와 우편함 [D2=1]개가 5장 격자 위치에 보이고, 달팽이는 시작 칸에 있다.
- R2-2. 편지 쪽으로 방향키/WASD를 한 번 누르면 달팽이가 한 칸을 0.60초 동안 가고 편지도 같은 방향으로 한 칸 함께 밀린다.
- R2-3. 편지 뒤가 벽·울타리·다른 편지·맵 가장자리면 달팽이와 편지 모두 움직이지 않는다. 달팽이는 편지·우편함 칸으로 걸어 들어가지 못한다(D22).
- R2-4. 편지를 우편함 칸으로 밀어 이동이 끝나면 그 편지가 화면에서 사라진다(D24). 이동 도중에는 사라지지 않는다(D17).
- R2-5. 편지를 줍거나 당길 수 없다: 달팽이가 편지 반대쪽으로 가도 편지는 따라오지 않는다.
- R2-6. 화면 [D5 위치]에 남은 시간 [D4=30]이 보이고 1초마다 1씩 줄어든다. 첫 1초 동안은 30으로 보인다(D23).
- R2-7. 남은 시간이 0이 되면 달팽이가 더 움직이지 않고 타이머는 0을 보인다. 이동 중이었다면 이동도 멈추고 그 편지는 배달되지 않는다(D21). (실패 화면은 goal-3)
- R2-8. 편지·우편함·타이머 숫자를 확대해 봐도 6장 8색 외의 색(번짐 포함)이 보이지 않는다(D26).
- R2-9. R1-1~R1-5가 그대로 동작한다(0.60초 이동, 벽·울타리 막힘, 768x576 표시, 16x12 맵, 8색).
### goal-3
- R2-10. 페이지를 열면 타이틀 화면이 보이고, [D9=Enter]를 누르기 전에는 달팽이가 움직이지 않고 타이머도 줄지 않는다. 이때 R은 아무 일도 하지 않는다(D10).
- R2-11. [D9]를 누르면 플레이 화면이 나오고 그 순간부터 타이머가 줄기 시작한다(D20). 시작 키와 같이 누른 방향 입력은 무시된다.
- R2-12. 마지막 편지가 우편함에 배달되면 즉시 클리어 화면이 보이고 타이머가 멈춘다.
- R2-13. 제한 시간 안에 다 배달하지 못해 0이 되면 실패 화면이 보인다. 시간이 남아 있는 동안은 실패 화면이 나오지 않는다.
- R2-14. 마지막 편지 배달과 시간 0이 같은 프레임이어도 클리어 화면이 보인다(D19). (사람이 재현하기 어려우면 해당 단위 테스트로 확인 + 사람이 결정을 승인)
- R2-15. 플레이 중 R을 누르면 달팽이·편지가 처음 칸으로, 타이머가 처음 값으로 돌아오고 이동 중이었어도 멈춘다(D11).
- R2-16. 클리어/실패 화면에서 R을 누르면 레벨 1이 처음 상태로 플레이가 다시 시작된다(D10).
- R2-17. 타이틀·클리어·실패 화면의 글자가 사람이 확정한 문구(D12)와 같고, 글자에도 8색 외의 색이 없다(D26).

## 9. 검증 계획
**단위 테스트(node --test test/), 기대값은 기획서 숫자:**
- 편지 한 칸 밀기 600ms 도착/599ms 미완료, 편지 커밋은 완료 시점(D17). 뒤가 벽/울타리/편지/가장자리면 pos·letters 불변.
- 편지가 M으로 들어가면 배달 +1·편지 제거, 달팽이 편지·우편함 칸 진입 불가(D22), 전부 배달 시 won.
- 타이머: 1000ms당 1초(ceil 표시 D23), 큰 dt는 100ms만 감산(2.1.1/D20), 클리어 프레임에는 감산 후 실패로 가지 않음(D18/D19), 잔여 0 -> lost.
- 불변식: won/lost 이후 tick 상태 불변(입력 무시, 타이머 정지), 이동 중 만료 시 이동 폐기·편지 미커밋(D21), 이동 완료 프레임에서도 타이머 감산 누락 없음.
- R 재시작: createState와 동일 상태(이동 중·타이머 초기화), 클리어/실패/타이틀에서의 R 동작(D10).
- 레벨 1 격자 16x12, `L` 개수 D1·`M` 개수 D2, 해법 키열 재생 테스트(13칸 -> 클리어, 7.8초 <= D4).
- 글리프·스프라이트 16x16(글리프는 정의 크기), 인덱스 0~7(R1-4, R1-5 확장).
- 기존 R1 테스트는 상태 형태 변경분만 갱신, 기대값은 유지.
**사람 브라우저 확인:** R2-1~R2-17 번호별. 스크린샷/fixture는 증거 아님. 완료 보고 = '무엇을 열어 어떤 번호를 볼지'.
**수동 점검:** `git diff`로 AGENTS.md 미변경, 기획서 밖 숫자 변경 없음 확인.
