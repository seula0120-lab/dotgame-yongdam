## 4. 사람이 정할 결정 D1~D14 (각각 기본값 = 에이전트 제안)
- D1 클리어 화면(레벨 1·2) 입력: 기본 **Enter → 다음 레벨(처음 상태, 시계 시작, Enter 프레임 방향 입력 버림)**. 화면 글자는 기존 7장 문구 재사용 `배달 완료` / `Enter로 시작`(새 글자 0). 대안: 2초 자동 진행(새 시간 규칙 필요), 다음 레벨로 즉시 진행(클리어 화면 생략). 대안은 클리어를 못 보게 하거나 새 규칙이 필요해 비권장.
- D2 플레이 중 R: 기존 2.1대로 **현재 레벨**만 처음 상태. 점수 변화 없음(점수는 클리어 때만 오르므로 잃을 것이 없다). 같은 프레임 방향 입력 버림(기존).
- D3 실패 화면 R: 기본 **실패한 그 레벨을 다시 시작, 이미 클리어한 레벨 점수는 유지**. 대안: 레벨 1·점수 0으로 처음부터(아케이드식, 난이도↑). 이유: 2.1 "R = 현재 레벨"과 일치, 레벨 3 실패마다 처음부터는 가혹.
- D4 최종 화면: 레벨 3 클리어 → 최종 화면. 최종 화면 R → **새 판(레벨 1, 점수 0, 플레이)**. 최종 화면 Enter는 무시(기존 클리어 규칙과 같음). 타이틀로 돌아가지 않는다(새로고침으로만).
- D5 점수 공식: 기본 **클리어 때 `100 × 그 레벨 편지 수 + 10 × (화면에 보이던 남은 시간 숫자)`**. 편지 수는 격자의 L 개수. 점수는 클리어 시에만 더해짐(실패·R은 무변화). 같은 프레임 클리어+시간 0이면 보너스 0. 결정적(난수·시각 없음). 대안: 편지당 점수만 / 이동 칸 수 감점. 최댓값(제안값 기준) 레벨별 ≈ 500/650/900, 합 2050 이내라 4자리.
- D6 플레이 중 점수 표시: 기본 **표시하지 않음**(맵 맨 윗줄은 타이머 하나, 레이아웃·색 변경 없음). 클리어 화면과 최종 화면에서만 `점수 N`. 대안: 윗줄 왼쪽에 누적 점수.
- D7 최고 점수 갱신 시점: 기본 **최종 화면에 도달했을 때, 이번 점수가 저장값보다 클 때만**. 실패·중도 포기는 저장 안 함. 대안: 레벨 클리어마다. 표시: 타이틀(저장값이 있을 때만 `최고 N`)과 최종 화면.
- D8 localStorage 허용 문구: 기본 키 **1개** `snailPostman.bestScore`(에이전트 제안), 값은 0 이상의 정수 십진 문자열 하나. 저장하는 것은 최고 점수뿐. 진행·레벨·이어하기 저장 없음. 서버·DB·계정 아님(브라우저 로컬). v5가 10장 "저장/이어하기"를 "진행 저장·이어하기(최고 점수 1개 저장은 허용)"로, 2.2 점수 행과 3장의 "저장하지 않고 상태에서 정해진다"를 "화면은 저장하지 않는다"로 고친다. AGENTS.md 금지 목록은 "서버, DB, 계정"이고 localStorage는 해당 없다고 보지만, AGENTS.md는 건드리지 않으며 이 해석은 사람이 서명으로 확정한다.
- D9 새 글자 최소안: 기본 **한글 4자 `점 수 최 고` 추가**(라벨 `점수 N`, `최고 N`, 숫자는 기존 0~9). 화면 문구 추가: 클리어(중간) = `배달 완료`/`점수 N`/`Enter로 시작`, 최종 = `배달 완료`/`점수 N`/`최고 N`(Enter 안내 없음으로 중간 클리어와 구분), 타이틀 = 기존 두 줄 + 저장값이 있으면 `최고 N`. 대안 0자안: 숫자만(라벨 없음, 모호). 대안 +2자: 최종 제목 `모두 배달 완료`(`모 두` 추가). 레벨 번호 `LEVEL`·`1/3` 표시는 하지 않는다(글자 추가 없음).
- D10 효과음 종류: 기본 5종 **밀기 시작(push), 배달(deliver), 레벨 클리어(clear), 전체 클리어(final), 실패(fail)**. 걷기 소리 없음(0.6초마다 반복되어 시끄러움). 대안: 걷기·막힘 소리 추가.

- D12 음소거·볼륨 UI 없음(설정 화면은 10장 범위 밖). 브라우저 탭 음소거만 가능. BGM 없음. 오디오는 첫 Enter 키 입력(사용자 제스처) 안에서 AudioContext를 만들거나 resume. 타이틀에서는 소리가 없다.


### 풀림 검증 (기계적)
1. 수작업 칸수는 위처럼 손으로 따라가 확인했다. 실제 검증은 실행자가 **repo 밖 임시 폴더**(예: `$TMPDIR`)에 일회용 BFS 풀이기를 만든다: 상태 = (달팽이 칸, 편지 칸 집합), 이동 = 4방향, 규칙은 2.2 밀기(뒤가 `.`/`M`이고 다른 편지 없음, 우편함 칸에 달팽이 못 들어감, M에 밀리면 편지 제거). 격자 3개(레벨 1 포함 대조용)에 대해 해 존재 여부와 최소 칸수를 출력하고, 위 풀이가 최소 이하인 것을 확인한다. 최소 칸수가 풀이보다 작으면 시간 여유가 더 있다는 뜻이라 제안 시간은 그대로 안전하다.
2. repo에는 BFS를 넣지 않는다(빌드·도구 추가 금지 취지). 대신 test/logic.test.js에 **풀이 재생 테스트**: 격자를 parseLevel로 읽고 위 키열을 `tick`으로 재생해 status `won`, 칸수·시간(34칸×600ms, 49칸×600ms에 해당하는 남은 시간 = 제한 − 칸수×0.60초, 100ms 상한 시계), 남은 편지 0을 단언. 기대값은 문서 5장 숫자.
3. 편지가 구석에 몰리는 막다른 길이 시작 상태에서 풀이를 막지 않음은 위 재생이 증명한다(풀이가 존재).

- R3-1. 레벨 1을 클리어하면 `배달 완료`와 `Enter로 시작`이 보이고, Enter를 누르면 레벨 2 맵(5장 격자: 편지 2, 우편함 1, 울타리 1)이 시작 칸에 달팽이와 함께 나타난다. 이때 Enter와 같이 누른 방향 입력은 무시된다.
- R3-2. 레벨 2 타이머는 45에서 시작하고 첫 1초 동안 45로 보이며, 클리어 화면이 떠 있는 동안과 Enter 전에는 줄지 않는다. 레벨 1은 30, 레벨 3은 60이다.
- R3-3. 5장의 레벨 2 풀이를 방향키로 따라 하면 제한 시간 안에 두 편지가 배달되고 클리어 화면이 나온다. 타이머는 클리어 순간 대략 24 이상을 보인다(34칸×0.60초 소요).
- R3-4. 레벨 2 클리어 후 Enter를 누르면 레벨 3 맵(편지 3)이 나오고, 풀이를 따라 하면 3개 모두 배달되어 클리어된다. 타이머는 클리어 순간 대략 30 이상(49칸×0.60초 소요).
- R3-5. 레벨 2, 3에서 시간이 0이 되면 `해가 졌어요`가 보인다. 이 화면에서 R을 누르면 **실패한 그 레벨**이 처음 상태로 다시 시작되고 타이머가 그 레벨 값으로 돌아간다(D3).
- R3-6. (goal-4 임시) 레벨 3을 클리어하면 일반 클리어 화면 `배달 완료`가 보이고 Enter는 아무 일도 하지 않으며 R은 레벨 1을 처음부터 시작한다. goal-5에서 최종 화면으로 바뀐다.
- R3-7. 플레이 중 R은 현재 레벨(레벨 3이면 레벨 3)만 처음 상태·타이머 처음 값으로 되돌리고 레벨 1로 가지 않는다.
- R3-8. 레벨 2·3 화면에 편지·우편함·울타리·벽·바닥이 5장 격자 위치에 보이고, 새 색이나 새 스프라이트 없이 6장 8색 안에서 번짐이 없다.
- R3-9. 레벨 2·3에서도 R2의 밀기·막힘·배달·타이머 규칙(R2-2~R2-7, R2-14, R2-15)이 그대로 동작하고 R1-1~R1-5가 유지된다.

### goal-5 (사운드, 점수, 최고 점수, 최종 화면)
- R3-10. 편지를 미는 이동이 시작될 때 짧은 "밀기" 소리가 한 번 난다. 편지 없이 걷거나 막힌 쪽으로 눌러도 소리가 나지 않는다(D10).
- R3-11. 편지가 우편함에 들어가 사라지는 순간(이동이 끝나는 순간) "배달" 소리가 난다. 이동 도중에는 나지 않는다. 마지막 편지 배달 프레임에는 배달 소리 대신 클리어 소리만 난다(D11).
- R3-12. 레벨 1·2를 클리어하면 "클리어" 소리, 레벨 3 클리어(최종 화면)에는 "전체 클리어" 소리, 시간이 0이 되어 실패 화면이 뜨면 "실패" 소리가 난다. 클리어를 못 했는데 클리어 소리가 나지 않는다.
- R3-13. 타이틀에서는 소리가 없고, 배경음악은 어느 화면에서도 없다. 첫 Enter 이후 소리가 난다. DevTools 콘솔에 오디오 자동재생 오류가 없고, Network 탭에 오디오 파일(mp3/wav/ogg 등) 요청이 없다.
- R3-14. 레벨 클리어 화면에 `점수 N`이 보이고 N = 100×(그 레벨 편지 수) + 10×(마지막 편지 배달 직전에 화면에 보이던 타이머 숫자)와 같다(사람이 타이머를 보고 계산). 점수는 레벨 1→2→3로 누적된다.
- R3-15. 시간 0 실패 후 R을 눌러 같은 레벨을 다시 해도, 이전 레벨들에서 쌓은 점수는 유지된다. 플레이 중 R로 점수가 줄지 않는다(D2, D3).
- R3-16. 레벨 3을 클리어하면 최종 화면에 `배달 완료`, `점수 N`(세 레벨 누적), `최고 B`가 보이고 `Enter로 시작`은 없다. Enter는 무시되고 R은 레벨 1을 점수 0으로 새로 시작한다.
- R3-17. 최종 화면의 점수가 저장된 최고 점수보다 크면 `최고`가 그 점수로 바뀌고, 페이지를 새로고침하면 타이틀에 `최고 N`이 보인다. 더 낮은 점수는 최고를 바꾸지 않는다. 저장 전(처음)에는 타이틀에 `최고` 줄이 없다.
- R3-18. DevTools Application > Local Storage에 이 게임의 키가 정확히 1개(`snailPostman.bestScore`)이고 값은 최고 점수 숫자뿐이다. 실패·중도 포기로는 값이 바뀌지 않는다.
- R3-19. 사이트 저장소가 막혀 있어도 게임이 평소처럼 진행되고 오류 화면이 없으며 `최고` 줄만 보이지 않는다. (사람이 재현하기 어려우면 단위 테스트로 확인한다: 던지는 가짜 storage)
- R3-20. 새로 나온 글자(`점 수 최 고`)와 숫자가 6장 8색(글자 7)만으로 번짐 없이 그려지고, 타이틀·클리어·실패·최종 화면의 문구가 7장 문구표와 같다. 음소거·볼륨·일시정지 UI는 없다.
- R3-21. R1·R2 항목(R2-1~R2-17은 R2-16만 v5 대체)이 그대로 동작한다.
- 단위 테스트(보조): 이벤트 발행(push/deliver/clear/final/fail, 같은 프레임 deliver+clear → clear 하나), 점수 공식(편지 수·남은 초에서), 클리어+시간 0 → 보너스 0, 최고 점수 갱신·저장 모듈(가짜 storage 주입: 빈 값, 손상값, 쓰기·읽기 예외), 합성 모듈(가짜 AudioContext로 주파수·길이 호출 기록 — 스케줄링만 증명, 실제 음은 사람이 들어야 함).

## 8. R2 코드 영향 (j)
- `createState(level)`: levelIndex·score·events 없음 → 두 번째 인자(기본 0, 0)로 확장하면 기존 테스트의 호출은 유지. `createTitleState`도 동일.
- `restart(state, level)`: 지금은 `createState(level)`이라 점수·레벨 번호가 사라진다 → levelIndex·score를 보존하도록 변경. 실패 R(D3)과 최종 R(새 판)이 갈라진다.
- `startGame(state, level)`: "레벨 1 처음"으로 고정. 새 판과 같은 경로로 유지 가능.
- `screenOf`: won 상태에서 마지막 레벨이면 final.
- `tick`: won 전이에서 점수 가산 + events. `status` 무변경 규칙("클리어나 실패가 된 뒤에는 상태가 바뀌지 않는다")은 그대로. 기존 테스트 중 상태 객체 전체를 deepEqual로 비교하는 것이 있으면 새 필드 때문에 깨질 수 있어 먼저 확인.
- `main.js`: `LEVEL_1` import와 모듈 최상위 `const level`이 레벨 1 고정 → 레벨 선택으로. `frame`의 action 처리(start/restart)는 "Enter가 클리어에서 다음 레벨" 케이스 추가.
- 테스트: `level1`/`L1` 고정, "클리어/실패에서 R은 레벨 1"(R2-16 대응), "문구는 7장 그대로", "7장 글자 모두 글리프"(17자 가정)는 v5 기준으로 갱신. 기대값은 v5 문서 숫자에서 가져온다.

1. design-v5 작성 → 사람이 D1~D14 확인·수정 후 서명 (커밋 `design-v5:`).
2. repo 밖 BFS로 5절 두 격자 풀림 확인(문서 서명 전에 해도 됨, 결과를 문서에 한 줄로).
