### 5.1 풀이 재생 테스트 설계 (기대값은 문서 숫자에서 유도)
- 재생: 키 하나마다 `tick(s, level, [dir], 0)` 1번(이동 시작, 시계 불변) 후 `tick(s, level, [], 100)` 6번(0.60초). 마지막 키까지 반복. 마지막 이동의 완료 프레임은 클리어이므로 시간을 깎지 않는다(2.2 ③이 ④보다 앞).
- 공식: 클리어 시 남은 ms = 제한 − (칸수×600 − 100). 레벨 1: 30000−7800+100=22300 → 표시 23. 레벨 2: 45000−20400+100=24700 → 25. 레벨 3: 60000−27000+100=33100 → 34. 단언: status won, 남은 편지 0, 위 ms. (칸수 대신 문서 5장 숫자 13/34/45와 제한 30000/45000/60000을 상수로 쓴다.)
- 점수(goal-5): 가산 = 100×편지 수 + 10×timerDisplay(클리어 프레임 상태). 레벨 1 200+230=430, 레벨 2 200+250=450, 레벨 3 300+340=640, 전체 재생 합 1520. 클리어 프레임은 시간을 깎지 않으므로 남은 시간 ≥1ms, 보너스는 항상 ≥10이다. "클리어+시간 0 → 보너스 0" 경우는 존재하지 않아 규칙·테스트에서 삭제. remainingMs===null이면 보너스 0.
- 점수 상한(사람 판정에도 쓰임): 사람은 최소 칸수보다 빨리 풀 수 없고(칸당 경과 ≥600ms, 마지막 프레임 ≤100ms가 시간 미차감) 가산은 레벨 1 ≤430, 레벨 2 ≤450, 레벨 3 ≤640(합 ≤1520).
- 풀이 테스트는 test/logic.test.js에 추가(기존 관례, test/index.js와 `node --test test/` 유지). 레벨별로 격자 파싱 값(편지 수, 시작 칸, 제한 시간 30000/45000/60000)도 단언.

- D15 최고 표시 규칙(저장 불가 포함): 타이틀 `최고 N`은 저장값을 읽는 데 성공하고 값이 있을 때만. 최종 화면 `최고 B`는 읽기·쓰기가 모두 성공했을 때만 보이고 B = max(저장값 또는 0, 이번 점수). 읽기나 쓰기가 실패(접근 거부, getter 예외, 손상값은 "없음"으로 취급)하면 **줄을 숨긴다**. 가짜 대체 저장(메모리 최고 점수) 없음. 실패는 console.warn 1회, 화면 오류 없음.

- D11 효과음 종류(기본 5종): push(밀기 시작), deliver(배달), clear(레벨 클리어), final(전체 클리어), fail(실패). 걷기 소리 없음(0.6초마다 반복돼 시끄러움). 대안: 걷기·막힘 소리 추가.

## 8. 구현 계약 (문서화되면 executor가 따를 것)
- **소리는 상태가 아니라 전이에서 도출**: 순수 `soundsOf(prev, next)`. 상태에 events 필드를 두지 않는다. 규칙: `next===prev` → []; push = prev.move==null && next.move?.push; deliver = 같은 레벨에서 next.delivered > prev.delivered; clear/final = prev.status playing→next won(레벨 3이면 final); fail = playing→lost; 같은 프레임 deliver+clear/final이면 clear/final만. 클리어·실패 화면에서 tick이 같은 객체를 돌려주므로 소리가 반복되지 않는다. main은 매 프레임 `prev=state` 보관 후 `soundsOf(prev, state)` 재생.
- **저장은 final 전이 신호로 1회**: main이 `screenOf(prev)!=="final" && screenOf(next)==="final"`일 때 storage.saveBest 1회 호출. 쓰기 직전 재읽기 후 큰 값만 저장. storage.js는 `window.localStorage` getter 자체를 try 안에서 평가(접근 거부 가능), getItem/setItem 예외·손상값을 모두 처리. logic.js는 import하지 않음. bestScore는 영속 외부 데이터라 logic 상태에 넣지 않고 main이 보유·render에 전달.
- **오디오 제스처**: main.js keydown 핸들러 안에서 모든 비반복 keydown마다 `audio.unlock()`를 동기·멱등 호출(AudioContext 생성/resume을 rAF가 아닌 제스처 안에서). 생성 실패 try/catch, resume() rejection 처리, ctx.state가 running이 아니면 소리 폐기(재개 시 몰림 방지). 파일 로드·fetch 없음.
- **레벨 소유**: levels.js는 `LEVELS=[{grid,timeLimitMs}×3]`(기존 LEVEL_1 상수 대체, 5장 격자 그대로 복사). logic.js는 `LEVEL_COUNT=3`(5장 "레벨 3개")을 두고 테스트가 `LEVELS.length`와 대조. 상태에 `levelIndex`. main은 프레임당 한 번 `level=LEVELS[state.levelIndex]`를 계산해 render/startGame/restart/tick에 같은 값 사용. `screenOf`: won이고 levelIndex===LEVEL_COUNT-1이면 `final`. 새 전이 함수(`advanceLevel` 등)는 해당 화면이 아니면 **같은 객체**를 반환(기존 `next!==state` 규칙 유지, 동일성 테스트).
- 상태 확장 순서: goal-4에서 `levelIndex`, goal-5에서 `score`. `createState(level, levelIndex=0, score=0)`로 확장해 기존 호출·테스트 유지. 기존 테스트에 상태 전체 deepEqual 없음(확인됨). 갱신 대상: "클리어/실패에서 R은 레벨 1"(R2-16 대응), "문구는 7장 그대로", "글리프 17자 가정", `level1`/`L1` 고정부(레벨 선택 인자화).
