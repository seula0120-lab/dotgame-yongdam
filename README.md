# 달팽이 우체부

달팽이 우체부가 해가 지기 전에 편지를 다 배달하는 한 화면짜리 도트 게임이다. 편지는 밀어서 우편함으로 옮긴다. 레벨은 3개이고, HTML + Canvas 2D + JavaScript ES modules로 만들었다. 외부 라이브러리, 빌드, 이미지·오디오 파일이 없다(효과음은 Web Audio로 합성한다).

기획의 유일한 기준은 [GAME_DESIGN.md](GAME_DESIGN.md)이고, 작업 규칙은 [AGENTS.md](AGENTS.md)에 있다. 이 README와 기획서가 다르면 기획서가 맞다.

## 실행

게임은 HTTP로 열어야 한다. 프로젝트 폴더에서 아래를 실행하고 브라우저에서 <http://localhost:8000>을 연다. 이 서버는 파일을 내려주는 정적 서버일 뿐이고 게임 서버가 아니다. (기획서 8장에서 확인한 브라우저: Chrome)

```
python3 -m http.server 8000
```

`index.html`을 더블클릭해 `file://`로 열면 화면이 비어 있다. 브라우저가 `file://`에서 ES module을 막기 때문이고, 오류가 아니라 예상된 동작이다.

## 조작법

| 키 | 동작 |
|---|---|
| 방향키 또는 W A S D | 달팽이를 한 칸 이동한다 (0.60초). 누르고 있어도 반복하지 않는다. 이동 중 입력은 무시한다 |
| Enter | 타이틀에서 게임 시작, 클리어(레벨 1·2) 화면에서 다음 레벨 시작 |
| R | 플레이 중에는 지금 레벨을 처음부터, `해가 졌어요` 화면에서는 실패한 레벨을 다시, 최종 화면에서는 새 판을 시작한다 |

화면별로 Enter와 R이 하는 일의 전체 표는 기획서 3장에 있다.

## 규칙 요약

- 달팽이가 편지 칸으로 이동하면 편지가 같은 방향으로 한 칸 밀린다. 편지를 줍거나 당길 수 없다.
- 편지 뒤가 벽, 울타리, 다른 편지, 맵 가장자리이면 달팽이도 편지도 움직이지 않는다. 달팽이는 우편함 칸에 들어갈 수 없고 편지만 들어간다.
- 레벨의 편지를 모두 우편함에 넣으면 클리어다. 제한 시간은 레벨 1이 30초, 레벨 2가 45초, 레벨 3이 60초이고, 0이 되면 실패다.
- 점수는 레벨을 클리어할 때 `100 × 편지 수 + 10 × 남은 시간(올림 초)`만큼 오른다. 최고 점수는 최종 화면에서 브라우저 localStorage의 키 `snailPostman.bestScore` 하나에만 저장한다.
- 달팽이는 오른쪽을 보고 시작하고, 왼쪽으로 이동이 시작되면 같은 그림을 좌우로 뒤집어 그린다.

## 테스트

Node.js만 있으면 된다. 프로젝트 폴더에서 실행한다.

```
node --test test/
```

테스트의 기대값은 기획서의 숫자(5장 풀이의 칸 수와 남은 시간, 점수, 효과음 합성값 등)에서 가져온다. 테스트가 통과했다고 완료는 아니다. 완료는 기획서 9장의 수용 기준을 사람이 브라우저에서 확인해야 한다.

## 폴더 구조

| 경로 | 내용 |
|---|---|
| `index.html` | 캔버스(논리 해상도 256x192, 화면 표시 768x576)와 `src/main.js` 로드 |
| `src/logic.js` | 순수 로직. 상태를 받아 새 상태를 돌려주며 canvas, 오디오, localStorage를 모른다 |
| `src/levels.js` | 레벨 문자 격자와 제한 시간 |
| `src/sprites.js` | 팔레트 인덱스 배열로 적은 스프라이트와 글자 글리프 |
| `src/strings.js` | 화면에 나오는 모든 문구 |
| `src/audio.js` | Web Audio 효과음 합성 |
| `src/storage.js` | 최고 점수 읽기와 쓰기 |
| `src/main.js` | 입력, 그리기, 프레임 루프 |
| `test/logic.test.js` | 테스트 (`test/index.js`가 불러온다) |

색은 기획서 6장의 8색만 쓰고, 글자도 캔버스 `fillText`가 아니라 비트맵 글리프로 그린다.

## 레벨 추가하기

**기획서가 먼저다.** 지금 기획서 5장은 "레벨은 3개이고 레벨 4 이상은 만들지 않는다"고 정하고 있고 10장도 레벨 4 이상을 범위 밖으로 둔다. 레벨을 더하려면 코드보다 먼저 기획서를 고치고 사람에게 서명을 받아야 한다(AGENTS.md).

1. **기획서를 고친다.** `GAME_DESIGN.md` 5장에 새 레벨의 문자 격자, 제한 시간, 5장의 다른 레벨처럼 한 가지 풀이(시험용)를 적는다. 5장의 "레벨은 3개"와 10장의 "레벨 4 이상" 문구, 점수 범위처럼 레벨 수에 기대는 9장 수용 기준(R3-14, R3-15의 최고 점수 상한 등)을 함께 고친다.
2. **격자를 `src/levels.js`에 그대로 복사한다.** 좌표를 따로 적지 않는다. 격자는 16열 x 12행이고 문자는 `#` 벽, `F` 울타리, `.` 바닥, `S` 달팽이 시작 칸(1개), `L` 편지, `M` 우편함이다. 바깥 테두리는 벽으로 둔다.

   ```js
   export const LEVEL_4 = [
     "################",
     // ... 12행
     "################",
   ];
   export const LEVEL_4_TIME_MS = 50000;
   ```

   파일 끝의 `LEVELS` 배열 맨 뒤에 `{ grid: LEVEL_4, timeMs: LEVEL_4_TIME_MS }`를 더한다. `src/main.js`는 `LEVELS`를 그대로 읽어 파싱하므로 고칠 것이 없다.
3. **`src/logic.js`의 `LEVEL_COUNT`를 새 레벨 수로 바꾼다.** 마지막 레벨을 클리어하면 최종 화면이 되는 판정이 이 상수에 기대고 있다.
4. **테스트를 더한다.** `test/logic.test.js`의 레벨 개수·제한 시간 테스트(`LEVELS.length`, `LEVEL_COUNT`)를 고치고, 새 레벨의 시작 칸·편지·우편함 좌표와 기획서 풀이를 재생하는 테스트를 더한다. 기대값은 기획서에 적은 숫자에서 가져온다. 예를 들어 풀이를 재생했을 때 클리어 시점의 남은 시간은 `제한 시간 − (칸 수 × 600ms − 100ms)`다.
5. **`node --test test/`를 통과시키고, 사람이 브라우저에서 새 레벨을 끝까지 풀어 본다.**

화면에 새 문구를 쓰는 경우에는 `src/strings.js`에 문구를 적고, 새 글자의 글리프를 `src/sprites.js`에 더해야 한다. 기획서 7장은 쓰는 글리프를 문구에 나온 글자로만 한정하므로 이것도 기획서를 먼저 고친다.
